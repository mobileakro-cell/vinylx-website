# job: daily-article

오늘자 인사이트 기사를 프로필의 발행량(보통 1편) 이내로 조사·작성·검증하고 발행한다.

## 0. 준비
- 프로필의 `timezone` 으로 오늘 날짜를 구한다: `TZ=<timezone> date +%F` → **DATE**.
- 프로필 "콘텐츠 저장 구조"에 적힌 스키마 문서(README 등)를 읽는다.
- 기존 기사 목록을 모두 훑어 slug·제목·주제·출처 조합을 파악한다. 오늘 날짜 기사가 이미 발행량만큼 있으면 새로 쓰지 않고 누락된 것(번역·채널 초안·검증)만 채운 뒤 보고한다.
- 프로필의 "문체 참고 기사"를 읽어 구조와 톤을 맞춘다.

## 0-1. 여러 편일 때
- 프로필 `publish.articles_per_run` 이 2 이상이면 1~6단계를 기사마다 반복한다. 같은 실행 안의 기사끼리 카테고리·지역(국내/해외)·출처가 겹치지 않게 한다.
- 상한일 뿐 목표가 아니다. 검증 가능한 주제가 1편분만 있으면 1편만 쓴다.

## 1. 주제 선정
- WebSearch 로 프로필 "조사 범위"의 최근 14일 신호를 찾는다. 한국어·영어 검색을 모두 쓰고 주제당 서로 다른 검색어로 3회 이상 교차 확인한다.
- 최근 7일 기사의 카테고리를 보고 덜 다룬 축을 고른다. 카테고리 값은 프로필 목록에 있는 것만 쓴다.
- 프로필 **금지 주제**와 주된 검색 의도가 겹치지 않는지 확인한다.
- 검증 가능한 출처 2개 이상을 확보하지 못하면 아무것도 커밋하지 않고 이유를 보고한다.

## 2. 기사 작성 (기본 언어)
- 파일 위치·이름·필수 필드는 프로필 "콘텐츠 저장 구조"를 정확히 따른다.
- 구조 기본형(프로필이 다르게 정하면 프로필 우선):
  - 리드 2~3문장: 핵심 답 + 왜 독자(고객사)에게 중요한가
  - 첫 섹션: 무슨 신호인가 + 데이터의 한계 한 문단
  - 번호 붙은 실무 판단 섹션 3~5개
  - 마지막: 독자가 바로 쓸 실행 문장(예: "기획서에 먼저 적을 질문")
- 프로필에 "회사의 시각" 필드가 정의돼 있으면 채운다: 이 이슈가 고객사의 실제 결정(개발·도입·운영)에 뜻하는 것 3문장. 회사 역량·실적을 지어내지 않는다.
- 제목·설명 길이 제한은 프로필을 따른다(카드 이미지에 들어가므로 짧게).

## 3. 이미지 필드
- 프로필 "이미지 스타일"에 따라 `visual` 을 채운다(concept/prompt/alt). 자동화가 채우는 필드(예: `visual.image`)는 쓰지 않는다.

## 4. 채널 초안
- `jobs/channel-drafts.md` 를 이 기사 하나에 대해 실행한다.

## 5. 번역
- 프로필 "번역" 항목이 있으면 그 형식대로 같은 slug 로 번역본을 추가한다. 섹션 수·순서는 원문과 같게, 자연스러운 현지 문장으로.

## 6. 검증
- `node .claude/skills/insight-agent/scripts/validate-article.mjs <새 기사 파일> --categories "<프로필 카테고리 쉼표목록>"` 실행. 실패하면 고친다.
- 프로필 "검증 명령"을 실행한다(타입 검사·빌드 등). 설치 실패 시 프로필의 대체 명령을 쓴다.
- `git status` 로 변경 파일이 프로필 "수정 허용 파일"뿐인지 확인한다.

## 7. 발행
- DRY_RUN 이면 여기서 멈추고 보고한다.
- 프로필 `publish.mode: local` 이면 커밋·push 하지 않는다(공개 전 사이트에 로컬로만 쌓는 모드). 프로필의 빌드 명령까지 실행하고, 보고에 "로컬 저장만 함"을 적는다. 저장소의 다른 미커밋 변경은 건드리지 않는다.
- 프로필 "커밋" 항목의 작성자·메시지 형식으로 허용 파일만 stage → commit → push.
