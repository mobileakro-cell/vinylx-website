# 공통 품질 규칙

사람의 검토 없이 공개 사이트에 그대로 배포된다는 전제로 쓴다.

## 1. 사실과 출처
- **지어내지 않는다.** 검색량, 시장 규모, 효능, 인증, 가격, 리드타임, 회사의 역량·실적은 출처나 프로필에 있는 것만 쓴다.
- 기사마다 신뢰할 수 있는 출처 **2개 이상**. 규제기관·공공기관, 리서치 기관, 원문 보도를 우선한다(사이트별 우선 출처는 프로필).
- 검증 순서: 먼저 WebFetch 로 URL 을 열어 인용할 사실을 확인한다.
  - 네트워크 정책 때문에 WebFetch 가 실패하면(EGRESS_BLOCKED 등) **우회하지 않는다.** WebSearch 결과에 실제로 나온 URL·제목·스니펫만 출처로 쓰고, 기사의 모든 숫자·사실은 스니펫에 문자 그대로 있어야 한다.
  - `sources[].url` 은 검색 결과의 URL 을 그대로 쓴다. `publishedAt` 은 확인될 때만 적는다.
- 출처가 다른 숫자를 합쳐 새 주장을 만들지 않는다. 원료·기초 연구를 완제품 효과로, 한 시장 데이터를 전체 시장으로 넓히지 않는다.
- "검색량이 높다/급증" 같은 표현은 Google Trends·네이버 데이터랩 등 확인 가능한 자료가 있을 때만 쓴다. 없으면 "시장·정책·현장 신호"로 쓴다.
- 기사 문장을 그대로 옮기지 않는다. 요약·분석·재구성한다.

## 2. 발행량과 품질 (검색·AI 인용 기준)
- 양보다 **색인되고 인용될 만한 한 편**. 프로필의 발행량 상한을 넘기지 않는다.
- 좋은 주제가 없으면 **0편이 정상**이다. 억지로 채우지 않는다.
- 기사 하나에 검색 의도 하나. 기존 기사와 같은 주제·같은 출처 조합은 다시 쓰지 않는다.
- 얕은 요약 대신 그 회사만 줄 수 있는 관점(프로필의 "회사의 시각")을 넣는다. 단, 회사 역량을 과장하지 않는다.
- 데이터의 한계(전망치, 특정 시장 한정, 표본 등)를 한 문단 밝힌다.

## 3. 금지 주제
- 프로필의 금지 주제(예: GEO 실험 대조군)와 **주된 검색 의도**가 겹치면 다른 주제를 고른다.
- 본문에서 한 줄 언급은 괜찮지만, 제목·리드·섹션 제목의 중심 주제가 되면 안 된다.

## 4. 이미지·SNS
- 이미지 생성 프롬프트에는 실제 브랜드명·제품명·사람 얼굴·텍스트를 넣지 않는다.
- SNS 문구는 기사 본문 복사가 아니라 채널에 맞게 다시 쓴다. 출처에 없는 숫자·주장은 SNS 에도 쓰지 않는다.
- SNS 는 **초안까지만** 만든다. 실제 게시는 사람이 승인 큐에서 한다(되돌리기 어려운 외부 공개).

## 5. 저장소 위생
- 프로필의 "수정 허용 파일" 외에는 건드리지 않는다. `git status` 로 확인한 뒤 해당 파일만 명시적으로 stage 한다(`git add -A` 금지).
- 비밀값(.env, API 키)을 읽거나 출력하지 않는다.
- push 가 거부되면 `git pull --rebase origin <branch>` 후 한 번 더 push 한다. 충돌이 나면 멈추고 보고한다.
