Generative UI가 만든 화면, 접근성은 누가 보증하는가

매번 달라지는 인터페이스 시대의 새로운 디자인 QA.

#생성형UI#접근성#디자인시스템

Generative UI는 사용자와 맥락에 맞춰 화면을 즉시 재구성한다. 고정된 시안을 검수하던 방식으로는 매번 다른 결과의 접근성과 안전성을 보장하기 어렵다. 디자인 시스템은 완성된 조각의 모음이 아니라, 어떤 결과도 안전하게 생성하는 규칙의 집합이 되어야 한다.

W3C는 생성형 UI를 주제로 상호운용성, 접근성, 프라이버시, 보안과 검증을 함께 다루는 표준 논의를 열었다. 생성형 UI가 실험을 넘어 제품 인프라로 이동하고 있다는 신호다.

검수의 단위도 화면에서 정책으로 바뀐다. 색상 대비, 초점 순서, 의미 구조, 취소 가능성을 생성 후에 확인하는 것이 아니라 생성 규칙 자체에 제약으로 넣어야 한다.

사용자에게는 화면이 바뀐 이유와 원래 구성으로 돌아가는 방법을 함께 제공해야 한다. 개인화는 통제권이 함께 있을 때만 유용하다.

FRAMEWORK

생성형 UI 설계 4단계

  1. STEP 01고정 영역과 가변 영역 나누기

    내비게이션, 결제·취소 버튼, 오류 메시지처럼 절대 생성되면 안 되는 영역을 먼저 정한다. AI가 바꿀 수 있는 것은 콘텐츠 배열·요약·추천 카드 같은 가변 영역으로 제한한다.

  2. STEP 02생성 규칙을 토큰과 제약으로 쓰기

    '파란 버튼'이 아니라 '주요 행동은 화면당 1개, 대비 4.5:1 이상, 터치 영역 44px 이상'처럼 검증 가능한 규칙으로 디자인 시스템을 다시 쓴다.

  3. STEP 03생성 직후 자동 검증

    렌더링 전에 대비, 제목 구조, 포커스 순서, 대체 텍스트를 자동으로 검사한다. 실패하면 생성 결과 대신 미리 준비한 기본 레이아웃을 보여준다.

  4. STEP 04사용자에게 되돌리기 제공

    '왜 이렇게 바뀌었나요?' 설명과 '기본 화면으로 보기' 스위치를 항상 같은 위치에 둔다.

TIP시안 몇 장을 검수하는 대신 대표 시나리오 수십 개를 자동으로 생성해 규칙 위반률을 측정해 보세요.

QUESTION FOR THE BRIEF화면이 매번 달라져도 사용자가 절대 잃지 않아야 할 제어와 정보는 무엇인가?

PLANNING CHECKLIST

  • 생성되면 안 되는 UI 영역 목록이 문서로 정의되어 있는가?
  • 디자인 시스템 규칙이 사람이 아닌 코드로 검증 가능한 형태인가?
  • 스크린리더 사용자가 생성된 화면에서도 같은 순서로 탐색할 수 있는가?
  • 생성이 실패하거나 느릴 때 보여줄 기본 화면이 있는가?
  • 사용자가 개인화를 끌 수 있고, 그 선택이 유지되는가?

WHAT TO MEASURE

  • 자동 접근성 검사 통과율
  • 기본 화면으로 되돌린 비율
  • 생성 화면에서의 작업 완료율
  • 보조기기 사용자 과업 성공률

TAKEAWAYS

  1. 컴포넌트보다 생성 규칙과 제약을 문서화한다
  2. 생성된 모든 상태에 자동 접근성 검증을 적용한다
  3. 사용자가 적응형 UI를 끄고 기본 화면으로 돌아갈 수 있게 한다
