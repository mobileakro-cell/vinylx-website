AI 에이전트의 신뢰는 '정답'이 아니라 '통제권'에서 시작된다

위임·승인·복구를 설계하는 Agent Experience의 핵심 원칙.

#AI에이전트#신뢰설계#AX

AI가 예약하고 결제하고 업무를 바꾸기 시작하면, 사용자에게 필요한 것은 더 매끄러운 채팅 화면이 아니라 언제든 개입할 수 있는 통제권이다. 설계의 중심은 응답 속도에서 위임 범위, 실행 전 승인, 진행 상태의 가시성, 실패 후 복구로 옮겨간다.

AX 논의의 중심은 '에이전트가 무엇을 할 수 있는가'에서 '사용자가 얼마나 안전하게 맡길 수 있는가'로 이동했다. 감독과 승인은 나중에 붙이는 보안 절차가 아니라 처음부터 사용 흐름의 일부여야 한다.

좋은 에이전트 UX는 실행 전에 계획과 영향 범위를 요약하고, 진행 중에는 현재 상태와 다음 행동을 드러낸다. 실패했을 때는 원인만 알리지 않고 되돌리기, 재시도, 사람에게 넘기기 같은 복구 경로를 즉시 제공한다.

여정 지도에는 사용자의 행동뿐 아니라 에이전트의 권한·불확실성·중단·복구 상태를 함께 그려야 한다. AX는 새로운 화면 스타일이 아니라 사람과 시스템 사이의 책임을 배분하는 서비스 설계다.

FRAMEWORK

에이전트 경험 설계 4단계

  1. STEP 01위임 범위 정의

    에이전트가 할 수 있는 일을 보기(조회) · 제안(초안) · 실행(변경) 세 단계로 나눈다. 처음에는 제안까지만 열고, 신뢰가 쌓이면 사용자가 실행 권한을 직접 넓히게 한다.

  2. STEP 02승인 지점 설계

    금액이 발생하거나, 되돌릴 수 없거나, 개인정보를 쓰는 행동은 반드시 실행 전에 요약을 보여주고 승인받는다. 나머지는 사후 알림으로 충분하다.

  3. STEP 03진행 상태 가시화

    지금 무엇을 하고 있는지, 다음에 무엇을 할지, 언제 끝나는지를 한 줄로 보여준다. 오래 걸리는 작업은 중간 결과와 중단 버튼을 함께 제공한다.

  4. STEP 04실패와 복구 설계

    실패 시 '무엇이 바뀌었는지 → 되돌리기 → 다시 시도 → 사람에게 넘기기' 순서의 복구 경로를 준비한다. 모든 실행 기록은 사용자가 다시 볼 수 있어야 한다.

TIP프로토타입은 성공 시나리오보다 잘못된 실행·중단·복구 시나리오부터 만들어 테스트하세요.

QUESTION FOR THE BRIEF이 에이전트가 실수했을 때 사용자는 10초 안에 무엇이 바뀌었고 어떻게 되돌릴지 알 수 있는가?

PLANNING CHECKLIST

  • 에이전트의 권한이 보기·제안·실행으로 구분되어 있는가?
  • 승인이 필요한 행동의 기준(금액, 비가역성, 민감정보)이 정의되어 있는가?
  • 사용자가 언제든 작업을 멈출 수 있는가?
  • 실행 기록에서 무엇이 바뀌었는지 확인하고 되돌릴 수 있는가?
  • 에이전트가 확신이 낮을 때 그 사실을 알리는가?

WHAT TO MEASURE

  • 승인 요청 대비 거절률
  • 실행 후 되돌리기 비율
  • 오류 발견부터 복구까지 걸린 시간
  • 사용자가 직접 넓힌 위임 범위

TAKEAWAYS

  1. 실행 전 계획과 영향 범위를 보여준다
  2. 중단·되돌리기·사람에게 넘기기를 기본 제어로 둔다
  3. 권한은 보기·제안·실행으로 나누고 최소 권한에서 시작한다
